# Discovery decision and finalization budget

The retained commerce run twenty-four reached its seventh model decision and
proposed another snapshot. The host correctly refused: a snapshot needs a new
decision followed by terminal mapping, while only one of the original eight
model calls remained. The model had not been told this allowance and still saw
all inspection tools. This was a model/host contract gap, not token, cost,
deadline, navigation-authority or native-cleanup exhaustion.

Work settings now carry an admission-frozen per-run model-call allowance. Its
default remains eight; the trusted application may narrow it to two through
eight. The same allowance gates every session turn, native inspection,
navigation and mapping admission. This is separate from the eight-pair replay
storage bound. Aggregate manifest token/cost budgets, account authority and
the original absolute deadline are unchanged.

For open discovery, immutable provider configuration binds the first call
identity and allowance. Each observation or Read/Locate continuation derives
the remaining decision calls from its exact call identity. A bounded developer
message exposes that count and the one call reserved for mapping. It is encoded
before whole-input measurement and policy reservation, never retained as stale
transcript progress. Navigation and scope replacement do not reset the count.

The last decision advertises only the already authorized Extract tool and
requires a tool response. The controller independently rejects any other
proposal before dispatch. Extraction still uses the existing schema, task
readiness, current-source verification, provider admission and durable closure;
the budget message cannot declare success. Missing facts must remain explicit
in the final answer. The reserved call is a call-slot reservation, not a waiver
of token, cost or deadline admission, so these limits may still refuse mapping.

Deterministic regressions exercise eight-call and four-call discovery through
the ordinary loopback provider, including repeated lookup misses, exact fresh
budget disclosure, final mapping and clean shutdown. A provider that ignores
the final decision's tool restriction is rejected without another observation.
Core tests check non-unit starting call identities, exhausted/foreign call
positions, immutable configuration, unchanged evidence and counted host bytes.
Live usefulness remains a separate qualification; these tests make no claim
that a real model obtains enough product evidence within the allowance.
