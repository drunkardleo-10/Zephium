INTEGRATION CONTRACTS

commands.workModelsReady(expectedProfile) returns WorkModelsReadyV1:
  { version: 1, profile: string, ready: boolean,
    missing_roles: WorkModelRole[], fault: WorkModelsFaultV1 | null }
missing_roles is [] when ready, otherwise ["lead"]. Decision stays internal.
Readiness means a lead model is configured with an available, non-refused key;
it does not promise billing, quota or network availability. Explicit choices
are preserved when their key becomes invalid or is removed.

frame/src/domain/ai/catalog.ts retains pickerGroups(models, role, endpoint)
  -> { ready: { provider, entries: WorkModelEntry[] }[], needsKey: provider[] }
The WorkModelEntry shape is unchanged. Curated entries precede provider-listed
entries; Cloud is excluded. Settings has an explicit More models action.
Provider status adds optional fault. Existing key states remain unchanged:
missing / set / valid / invalid. Only wrong-key failures invalidate a key.

WorkCliRowV1 adds optional path. WorkServerOutcomeV1 adds "cancelled".
Existing connection row/tool shapes are unchanged. Exhaustive consumers of
WorkServerOutcomeV1 must handle the new cancelled case.

commands.workPreviewConnection(profile, draft) connects, lists tools, and
returns WorkServerCheckV1 without saving configuration or real vault items.
OAuth drafts use memory tokens until Save. Save requires the same successful
draft within five minutes; editing the draft requires another check. Enable
and disable alone do not require a new check. Held secrets are never forwarded
to a changed endpoint/command. Removal clears all server vault accounts.

BROWSER OWNER INTEGRATION STILL REQUIRED

Listen on the privileged window for CustomEvent("zephium:connection-sign-in").
Payload for started / finished:
  { version: 1, phase, profile, id, request_id }
Payload for open_requested also includes operation_id from OpenUrl admission.

1. On open_requested, associate that operation with the actual new tab;
   remember the Settings destination and activate the authorization tab.
   Buffer an operation result if it arrives before this event.
2. On finished, close only the associated authorization tab and restore the
   remembered Settings destination. This fires after success, failure,
   cancellation or timeout. Do not infer success from this event: the command
   result supplies the final connected/tools or retry state.
3. If the person closes that tab first, call
   commands.workCancelConnectionSignIn(profile, id, request_id).
   Only the matching request can be cancelled; ignore late events for old
   requests. The flow has a five-minute total timeout and drops its listener.
4. Resume notification may dispatch CustomEvent("zephium:connections-resume")
   to the privileged window. Settings already coalesces online events and
   detects a timer gap after wake. This subscription exists while Connections
   is mounted. A global background reconnect service outside Settings is not
   added by this branch. Work's existing connection-on-use path is retained.

No browser/tab owner files or canvas files were changed. Native tab focus and
closing are not complete until this hook is integrated.
