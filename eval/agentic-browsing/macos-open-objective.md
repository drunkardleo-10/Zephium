# Actual-app public open-objective candidate

Status: implementation candidate; no GUI launch, Keychain access, provider call,
site outcome, or usefulness qualification is claimed by this document.

The development feature `macos-work-discovery-probe` reuses the actual
application navigation witness's Tauri startup, actor-selected browser profile,
credential worker, ordinary trusted admission, observer and normal shutdown.
It does not start a retained-resource witness or a second controller. The same
isolated `app.zephium.work-navigation-probe` bundle identity/configuration is used;
source, feature and bundle hashes distinguish this new candidate. Preserve any
existing application root intact before a new explicitly authorized run, as
described in [the navigation evidence protocol](macos-application-navigation.md).

The question starts at React's Learn index and asks why three
`setNumber(number + 1)` calls in one click increase the counter only once, and
how to make that click increase it three times. No destination URL, expected
heading, correct answer, or predetermined hop count is supplied. The policy
allows at most two observed same-origin document links below `/learn/`, initial
baseline reads and one schema-bound answer. The original eight-operation,
100,000-token, 100,000-micro-USD and 150-second bounds remain unchanged.
An answer can complete after one hop; the remaining hop is an allowance.

This explicitly public witness sets `store:true` for inspectable Luna calls;
ordinary production/BYOK construction remains stateless. Do not use the public
witness with a private or signed-in profile. The fresh isolated application
profile and unchanged binding checks establish the scope of this candidate.

Build only the `.app`, without launching:

```sh
pnpm -C desktop exec tauri build --debug --config tauri.work-navigation-probe.conf.json --features macos-work-discovery-probe --bundles app --ci --no-sign
```

Before a live run, record a clean source commit, exact executable SHA-256 and
deterministic whole-bundle manifest using the existing `bundle-manifest-v1.mjs`.
Review the frozen question, native/site constraints and provider retention.
Use the existing one-shot foreground admission procedure, preserve the isolated
Store and diagnostic output, and compare the unchanged bundle manifest after
exit. There is no automatic provider, navigation or GUI retry.

Acceptance has two independent parts:

- Execution evidence: at least one and at most two observed-link navigation
  proposals, source-backed `ModelMapped` extraction, ordinary durable
  `Succeeded`, exact settled model accounting, original observer join, and
  clean normal application shutdown. The observer does not call this factual
  or useful success. Every destination comes from the exact current delivered
  link observation; native commit and fresh-source validation remain required.
- Manual judgment: inspect all retained Luna calls in the provider dashboard,
  including the actual delivered link inventory, chosen routes, destination
  sources and mapped answer. Confirm the explanation addresses the practical
  question accurately, offers an actionable correction and cites supporting
  current-page evidence. Record the answer, supporting source URLs and the
  human judgment in the evidence record after review. Mechanical success does
  not imply a passing manual judgment.

The local trace prints only content-free counts, including `links` and
`destination_bytes` on each observed document, and settled request/semantic
bytes, tokens, cost and latency. Record these alongside actual provider traces
to measure the cost of link disclosure. Correlate every retained response to
the exact single run and model-call order; retaining responses by itself is
not proof that someone inspected them. Do not claim a public trace URL exists
unless one has actually been obtained and checked.

Known limits to test honestly: hidden WKWebView scheduling, bounded page/text
projection, excluded redirects/fragments, at most two hops and current-page-only
citations. If this task encounters one, preserve the failed trace and identify
the concrete blocker before changing a ceiling or adding a capability. The
candidate is not a general browsing, authentication, multi-source synthesis,
Windows live-workflow, concurrent Browse, or multi-agent qualification.
